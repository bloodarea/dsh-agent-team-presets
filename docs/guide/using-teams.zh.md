# 使用团队

如何配置一个团队、在会话中启用它，以及设置页每个字段控制什么。

[English](<using-teams.md>) · [文档索引](../index.zh.md) · [README](../../README.zh.md)

## 配置与使用团队

1. 打开 **设置 → 智能体团队预设**。
2. 选择内置团队、复制已有团队，或点击 **新建团队**。
3. 设置团队名称、用途、展示元数据、所属分类、队长与成员角色。
4. 为各成员配置独立的模型路由、推理强度、工具权限与专属 Team Skill。
5. 点击共享页脚中的 **保存**。未保存前的修改均为草稿。
6. 在会话输入区的团队选择器中选中该团队，要求队长调度角色完成任务。

例如针对包含研发与审查角色的团队：

> 使用当前团队。让研发执行者完成约定改动并补全回归测试，再让独立审查员进行质量检查。最后汇总改动、测试结果与剩余风险。

预设角色是召唤模板。每次召唤会创建带唯一 target（如 `executor` 或 `executor-2`）的实例。需要继续已有成员工作时，使用 `send_message` 发向返回的 target，而不是重新创建实例。

选择 **不加载预设（No preset）** 会在队长与队员全部空闲后卸载团队应用，恢复常规会话行为，不改变已选模型。

### 与单个成员单独对话

在输入区团队选择器中悬浮某个团队，会展开成员面板：队长排在最前，模型一栏显示 **会话模型**；其后是各队员的「提供方 · 模型」与角色描述。

- 选择 **队长** 即常规应用该团队：队长主导本会话、可召唤队员，并继续使用会话已选的模型。
- 选择 **队员** 即与该成员单独对话：该成员的角色卡（名称、角色描述、独立系统提示词）成为本会话 persona，其工具策略与已分配的 Team Skill 生效，不再安装队长简报与 `spawn_team_member`；同时会话模型自动切换为该成员配置的提供方/模型与推理强度。未配置路由的成员保持会话当前模型。
- 再切回队长不会恢复旧模型：队长始终跟随会话当前所选模型。
- 角色与模型的切换和团队切换一样，会等待运行中的任务到达边界；若所选成员已被删除，则拒绝该选择并保持会话锁定，绝不静默回退到队长。

### 字段说明

| 字段 | 用途 |
|---|---|
| 团队名称与用途 | 标识预设，并说明适合处理什么工作。 |
| 所属分类 | 归入自建分类，便于在列表与选择器中归纳。 |
| 展示元数据 | 简介、标签、适用场景、推荐任务与备注。仅供界面展示与检索，不注入 LLM 运行时上下文。 |
| 队长 | 当前会话的主智能体。非空的队长提示词会替换其 persona 前缀；队长使用会话当前模型。 |
| 成员 | 队长可召唤的角色模板。 |
| 名称 | 角色显示名称与 target 基础。ASCII 字母/数字/连字符（最多 64 字符，不能为 `lead`）。 |
| 描述 | 说明角色职责，供队长选人决策（建议 200 字符以内）。 |
| 颜色 | 在设置页和名册中区分角色的强调色。 |
| 提供商 / 模型 | 仅成员可配置。从部署的模型目录中独立选择路由。 |
| 推理强度 | 仅成员可配置。取决于模型支持，留空使用路由默认值。 |
| 允许的工具 | 独立配置所有工具或自定义白名单策略。 |
| Team Skills | 专属技能分配。成员被召唤时，仅在该 Agent 作用域内注册生效。 |
| 系统提示词 | 固定的角色指令。`{{variable}}` 会作为模板变量处理。 |

### 内置预设

全新安装会初始化九个可编辑的团队，划分为两大系列——三个研发规模团队与六个工作模式团队：

| 系列 | 团队 |
|---|---|
| **研发规模系列** | 轻量研发团队 `builtin-lightweight` · 标准研发团队 `builtin-standard` · 全栈软件研发团队 `builtin-fullstack` |
| **工作模式系列** | 需求探索 `builtin-discovery` · 架构规划 `builtin-planning` · 既定工作流执行 `builtin-workflow` · 工程研发协作 `builtin-engineering` · 独立代码与安全审计 `builtin-audit` · 科研协作 `builtin-research` |

每个预设的角色、适用场景，以及这些角色拿到哪些团队技能，见[内置团队](../builtin-teams.md)与[内置团队技能](../builtin-team-skills.md)。

内置预设在每个 profile 中只初始化一次，用户对其编辑或删除会被持久记忆。这也意味着如果团队列表是因为别的原因丢的（手改配置、配置回滚），插件不会自己补回来：宿主会写一条 warn 日志，设置页顶部也会出现提示，指向 **恢复内置预设**（它只改草稿，恢复后要保存）。恢复会重置内置字段与角色，但完整保留匹配角色的模型路由与工具策略。

## 展示元数据、本地分类与搜索

### 纯前端展示元数据

每个预设均支持完整的展示元数据：

- **简介 (Summary)**：卡片与选择器中展示的一句话定位。
- **标签 (Tags)**：用于快速分类与检索的关键词。
- **适用场景 (Use Cases)**：适合该团队的项目与工作类型。
- **推荐任务 (Quick Prompts)**：选中该团队后展示的推荐快捷任务。
- **备注 (Notes)**：协作注意事项或说明。

**Token 保护：** 展示元数据保存在预设文档中，仅在界面与检索中展示，**绝不注入 LLM 运行时提示词中**，不占用任何模型上下文。

### 本地分类与层级筛选

- **分类管理页：** 点击设置列表中的 **管理团队预设分类** 即可进入独立管理页。支持新建分类、重命名、上下移动排序以及删除分类，清晰显示每个分类下的团队数量。
- **本地隔离：** 分类与团队分类归属仅保存在当前 profile 本地，导出预设时**绝不会随文件导出**。
- **双排联动筛选：**
  - **来源 (Source)：** 全部、插件内置、自定义。
  - **分类 (Category)：** 针对内置团队显示研发规模与工作模式两大系列；针对自定义团队显示用户自建分类，互斥切换。
- **实时搜索：** 输入关键词即时全文检索名称、简介、标签、适用场景与推荐任务，并实时显示匹配数量。
- **输入区联动：** 会话输入区的团队选择器完全镜像支持上述来源筛选与搜索能力，并将 `不使用团队` 固顶在最上方。
