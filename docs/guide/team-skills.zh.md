# 私有团队技能

本插件自带一套团队技能（Team Skill）私有库：导入的技能文件夹或 `.zip` 包存放在插件专属存储中，并且**只在被分配成员自己的 Agent 作用域内**注册。新装环境还随包提供 14 个内置技能，已默认绑定到内置团队的各角色；完整清单见[内置团队技能](<../builtin-team-skills.zh.md>)。

[English](<team-skills.md>) · [文档索引](../index.zh.md) · [README](../../README.zh.md)

## 私有库存储与严格作用域隔离

传统 Harness 技能一般注册到全局环境，所有智能体都能看到。本插件实现了 Team Skill 私有技能子系统：

1. **私有库：** 技能统一存放在插件专属目录（`~/.dsh/agent-team-presets/team-skills` 或独立存储域），与宿主、Profile 的技能相互隔离。
2. **角色 Agent 作用域隔离：** 成员被召唤时，其绑定的专属技能**严格仅在该成员的 Agent Scope 内注册**。其他队员和队长既看不到也调不到，除非同样把这些技能显式分配给他们。
3. **官方内置技能：** 随包提供 14 个技能，分工作流型、交付型与方法型三类（10 / 2 / 2），默认绑定到内置团队的各角色。完整清单、各角色默认绑定与分类筛选见[内置团队技能](<../builtin-team-skills.zh.md>)；`agent-subagent-orchestration` 只绑定队长与执行者，顾问保持单线程。
4. **本地副本与恢复：** 内置技能只读。每份可编辑副本都有独立的编号名称，创建时可选择切换已绑定内置技能的角色。恢复会重置副本内容，并将使用该副本的角色切回内置版。
5. **分类筛选：** 团队技能库与成员分配网格的列表顶部各有一个分类下拉框（全部分类 / 工作流型 / 交付型 / 方法型 / 自定义）。单条技能的展示方式不变；筛选只影响列出哪些技能，不影响某个角色持有哪些技能，成员页标题也始终按全部已安装技能统计。
6. **随包技能的中英文名：** 界面按当前语言显示技能名——中文界面显示「Git 提交与发布规范」，英文界面显示 `git-release-hygiene`。这张映射表**仅用于展示**：模型读到的技能目录、存储的绑定、预设文档与磁盘上的资产目录一律仍是英文 `skillId`，因此切换语言或修改显示名都不会动存储格式，也不会破坏跨部署导入。本版本未收录的技能继续显示其英文 id。
7. **来源标签与色标：** 各视图都会给出按来源区分的色标：

    | 来源 | 界面显示 | 颜色 |
    |---|---|---|
    | 插件内置（Built-in） | 插件内置 | 蓝色 |
    | 自定义（Custom） | 自定义 | 紫色 |
    | 本地副本（Override） | 本地副本 | 琥珀色 |

隔离在创建成员时就已落实，而不是事后补：创建流程会等待该 Agent 自身的注册完成，因此无法发布技能的部署在创建阶段即被拒绝并给出原因，而不是先起一个空技能目录；私有库读不出来时同样拒绝，而不会把「读不到」当成「没有分配」。

## 导入、目录扫描与依赖守护

- **文件夹导入：** 在 Web 界面选择外部技能文件夹，将它添加到技能库。
- **扫描导入目录：** 用 `SKILL.md` 里的 `name` 识别技能。点击「扫描导入目录」后，发布新技能和已有技能的新版本。更新保留角色绑定和依赖设置。包名撞到内置技能时会被拒绝。
- **编辑扫描导入的技能：** 打开技能库时会检测来源目录的文件变化，包括文件路径和二进制资源。直接修改磁盘后，点击「扫描导入目录」发布新版。通过技能面板保存时，修改写回来源目录并立即发布。若磁盘已有待更新内容，请先扫描再保存。来源目录被移除后，上一版技能及其绑定仍然可用。

团队技能的依赖单独保存在技能库的资产元数据中。导入会原样保留 `SKILL.md` 的字节，并对 YAML frontmatter 中显式出现的顶层 `executables`、`mcpServers` 和 `otherSkills` 字段逐项提示。无论字段值是什么，都不会应用为依赖配置。

Web 界面的依赖面板仅供查看。要修改可编辑技能的依赖，请让 DSH 智能体调用 `set_team_skill_dependencies`，传入技能名或资产 ID，并将完整的依赖声明作为 `dependencies_json` 字符串传给工具。需要清除某类依赖时，可将对应数组设为空。`otherSkills` 使用资产 ID，可通过 `list_team_skills` 查询对应的 `assetId`。

以下示例为名为 `report-writer` 的技能设置依赖。

```json
{
  "skill_id": "report-writer",
  "dependencies_json": "{\"executables\":[\"pandoc\"],\"mcpServers\":[{\"serverName\":\"docs\",\"required\":true}],\"otherSkills\":[\"custom:report-style\"]}"
}
```

| 字段 | 如何准备依赖 | 插件如何检查 |
|---|---|---|
| `executables` | 单独安装各命令，并将其加入运行中的 DSH 进程能看到的 `PATH`。Windows 查找时还会使用 `PATHEXT`。 | 每项都必须能找到可执行文件。缺失命令会阻断分配（`dependency-missing`）。 |
| `mcpServers` | 在 DSH 的 Profile 或组合配置中配置并启用服务。服务工具可用后，在相应角色的工具策略中授权 `mcp__<server>__<name>` 工具。 | 显示声明，标记必需服务为 `unverified`。MCP 声明不会阻断分配，也不会建立连接。 |
| `otherSkills` | 单独安装声明的团队技能。要让角色能够使用其中一项，还要把它单独分配给该角色。 | 检查各资产 ID 是否存在于技能库。缺失资产会阻断分配（`dependency-missing`）。 |

**强阻断保护的删除：** 技能只要被任何团队角色分配、被运行中的成员占用，或被其他技能依赖，删除即被阻断。删除确认框会列出所有持有者（团队与角色，例如 `标准研发团队 → executor`），并在这些绑定解除前保持确认按钮禁用。

## 分享预设

**导出**将一个团队保存为 JSON 文档（格式版本 2）。**导入预设**读取该文档并暂存到编辑器中。

- **分享的字段：** 团队名称、用途、展示元数据（简介、标签、适用场景、推荐任务、备注），以及队长与成员的名称、描述、提示词、颜色。
- **内置技能绑定：** 版本 2 可通过 `officialSkills` 声明内置技能 ID 与角色名的对应关系。导入预览会提示无效声明，以及当前环境里缺少的内置技能。内置团队仍使用随包默认绑定。预设文件不携带自定义绑定或技能文件。
- **本地字段：** 模型路由、推理强度、工具权限与本地分类归属**绝不导出**；携带这些字段的文档在导入时被拒绝。
- **名称冲突：** 可覆盖已有预设，或改名新建。覆盖时会保留匹配角色上的本地路由与工具策略。
- 执行任务前请先审阅导入的提示词，尤其是来自第三方的文档。
