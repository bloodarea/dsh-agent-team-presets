# 子代理卡片预设标签

**dsh-context**（顶部编队）与 **dsh-better-sidebar**（右侧任务管理）里的子代理卡片，可以给本插件创建的子代理加上一个 `预设` 小标签。到目前为止这两个目标插件都还没有发布该服务，因此本插件为固定的一组版本随包提供预构建替换包，并在设置页里安装。

[English](<integrations.md>) · [文档索引](../index.zh.md) · [README](../../README.zh.md)

## 接入方式

标签是一个适配器，不是依赖：

- **按目标启用。** 目标插件必须提供自己的可选卡片标签服务（`contextAgentCardBadges` / `betterSidebarAgentCardBadges`，协议版本 1）。只有该服务出现时本插件才注册进去；本插件不依赖这两个包，两者都没装时行为完全不变。
- **精确身份。** 只有卡片对应的真实子会话 ID 与创建前写入的持久成员快照一致时才会显示标签，因此普通子代理与工作流占位节点不会被误标。查询只读已存储的记录，不会唤醒或读取卡片对应的 Agent。
- **不改变布局。** 标签是一个行内主题色小块，高度固定；不新增卡片行，并在既有标签区内裁剪。

## 在设置页里安装

替换包在 **设置 → 团队预设 → 插件联动** 中提供，每个目标一行：

| 目标插件 | 本版补丁适配的版本 | 该行可执行的操作 |
| --- | --- | --- |
| `dsh-context` | 0.84.0、0.84.1、0.85.0、0.85.1、0.87.0 | 安装补丁 / 卸载补丁 |
| `dsh-better-sidebar` | 0.32.0、0.32.1 | 安装补丁 / 卸载补丁 |

每一行报告自己的真实状态，页面不做猜测：`not installed`、`version not supported`、`not patched`、`patched`、`modified by something else`。出现 `version not supported` 时，该行会用你的语言点名**已安装的版本**与**本版最高适配的版本**——这时唯一要决定的就是升级哪一侧。**安装补丁**会先弹出确认框，备份目标插件的 `lib/client.js`，再写入本插件用同一份源码构建的替换包；**卸载补丁**从该备份还原并删除备份。

**不需要重启，也不需要刷新页面。** 运行中的服务器由 `client-hmr` 持续轮询每个插件的浏览器包，发现变化就重新发布（`clientModules.rebuilt`），页面随之就地重新加载该插件——约一秒后该行变为 `active`，卡片上的标签同时出现。若某行停留在 `patched` 而没有变为 `active`，刷新一次页面即可。

### 安全规则

- 如果目标插件的浏览器包既不是发布版、也不是本插件的替换版，操作会被拒绝：覆盖它等于毁掉一份本插件无法重现的改动。
- 每一行按**实际安装的版本**判定状态，并列出本版为其准备替换包的全部版本；不在列表中的版本显示 `version not supported`。支持新版本是一次「校验后重建」，不需要改代码（见下文）。
- 升级已打补丁的目标插件会覆盖其浏览器包，补丁随之消失，该行会重新显示 `not patched`。

### 跟进上游新版本

上游发版后用下面的命令跟进：

```sh
node tools/card-patches.mjs rebuild --target <id> --version <version> --write
```

它会克隆对应版本、应用源码补丁、重新构建，并且只有在重建后的包仍然注册卡片服务时才允许发布。新增版本不会挤掉旧版本；随包的 `assets/card-patches/catalog.json` 可以在不改代码的情况下覆盖新版本。

如果不希望使用随包构建，同样的改动也以源码补丁形式放在 [`contrib/agent-card-badges`](../../contrib/agent-card-badges/README.md)，可自行应用到匹配版本并重新构建；这些改动同样是可直接提交给目标维护者的上游改动。
