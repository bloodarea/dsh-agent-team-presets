# 工具与权限

根会话向智能体开放六个工具，用于读取与维护团队预设及团队技能；队长与每个成员各自持有一套工具策略。本文记录这组工具面、两种策略模式、成员首轮所依赖的保证，以及白名单的边界在哪里。

[English](<tools-and-permissions.md>) · [文档索引](../index.zh.md) · [README](../../README.zh.md)

## 面向智能体的工具

根会话注册一组工具，在受工具策略允许时，智能体可直接以程序方式查询或维护预设及技能。

### 预设管理工具

- **`get_team_preset`**：读取指定或当前选中的团队预设，返回其用途、角色描述、提示词、名册及设置修订号。
- **`update_team_preset`**：使用 CAS 修订号更新团队／队长描述及成员提示词、描述；需用户直接发起并由 Host 审批确认。若相关成员正在执行，则返回 `team-busy`。

### 团队技能工具

- **`list_team_skills`**：列出私有库中已安装的团队技能、来源、依赖项及角色分配状态。
- **`assign_team_skill`**：为某个团队的角色分配一个团队技能（作用域限定在该 Agent）。
- **`unassign_team_skill`**：解除某个角色的团队技能分配。
- **`remove_team_skill`**：从私有库删除团队技能，受阻断规则保护。

两个预设工具作用于当前 profile 配置中的团队记录，而不是随包目录：经 `update_team_preset` 的修改只改变本 profile 正在运行的团队，不会改写内置预设。技能工具作用于 [团队技能](../guide/team-skills.md) 所述的私有库，分配规则也由那里定义。

## 策略模式

队长与每个成员各自持有一套策略，共有两种模式：

| 模式 | 允许什么 |
|---|---|
| **默认所有工具** | 除部署权限与角色规则外，不增加额外白名单限制。 |
| **自定义可用工具** | 仅允许选中的工具。协作工具（`send_message`、`list_agents`、`team_task_*`）如需使用必须显式勾选。 |

队长与成员策略完全独立：给队长放行的工具不会顺带放行给成员。

**`skill` 工具始终放行，且不作为可选项呈现。** 它只负责发布技能目录并加载指令文本，不授予能力；而宿主会把整个目录从看不到该工具的角色那里收起。因此自定义白名单无法移除它，设置页也不再列出它——一个永远不会生效的勾选框只会误导使用者。旧版本写入、仍包含该项的配置照常加载：该名字被隐式放行，不会被提示为"不可用"，也不需要手动删除。

## PTC 下的自定义工具白名单

**自定义工具白名单在 PTC 下通过给该会话一个自己的 native 面来工作。** 宿主无法在释放执行器后恢复继承，所以插件从不主动释放：在 PTC 预设下它把宿主自带的 native 工具执行器挂到该会话的 Agent 作用域，部署级执行器保持原样。代价是明确的：该会话此后不再使用 `run_code`，而其他会话与「所有工具」模式继续走 PTC。若挂载失败、或挂载后工具面仍暴露 PTC 传输，则应用被拒绝且不留残留——因为从未释放过任何执行器。

## 成员首轮能保证什么

已分配的团队技能只有在成员真正发问的那一轮能被加载才有意义，因此插件把注册放进成员创建流程，而不是留给后台：

- **成员**：创建边会等待该 Agent 自己的注册完成后才结束。角色持有已分配的团队技能、但本次部署无法发布它时（未组合技能服务、私有库不可读、注册被拒），创建会被**明确拒绝**并给出原因，而不是在空目录下启动、让所有界面仍显示"已分配"。没有任何分配的角色，在未组合技能服务的部署上照常创建。
- **队长**：同一注册在 Session 创建边、依赖的团队应用之后完成。队长分配发布失败不会拒队——已在运行的 Session 不能因此失去能力策略——失败会以该 Agent 身份被报告出来。
- **"库不可读"不等于"库为空"。** 私有库打不开时，插件无法枚举任何角色的绑定，因此按"不可知"拒绝成员创建，而不是把未知当成"没有分配"。修复库路径（或重新开始）即可恢复。

## 安全边界

- 白名单**不是文件系统、进程或网络沙箱**。允许 bash 等具备执行能力的工具，它们仍保留其原生系统能力。请照常维护 Harness 的沙箱与审批策略。
- 自定义策略模式禁止通用 `run_code` 与普通 `subagent` / `workflow` 委派，以维持严格的策略契约。需要委派时请使用预设团队成员。
- 受管成员恢复时必须能读取其持久配置。记录缺失或损坏时严正拒绝，绝不回退为不受限的默认状态。
