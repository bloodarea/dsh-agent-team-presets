# 架构维度的衰减风险

> 本文是主 Skill 的按需参考资料。仅在架构设计、技术债判断或跨模块问题定位时读取；日常实现与局部修复不需要它。

本清单只保留**结构性**风险与影响架构判断的部分。函数级可读性、命名、测试质量属于审查员的清单，不在本文重复。

每条按：**症状 → 出处 → 后果 → 最小修复方向** 记录。诊断未完成前不要先给方案。

## R2 变更传播（架构视角）

- 症状：改一个能力要动 3 个以上无关联模块；同一模块为多个业务原因而改；一次变更触碰超过 5 个文件；跨层契约未定就先各自实现，导致后续改动处处受牵制。
- 出处：Fowler Shotgun Surgery / Divergent Change；Hunt & Thomas 正交性；Brooks《人月神话》第 2 章（沟通成本即传播半径）。
- 后果：回归面随调用方数量超线性增长，交付节奏被协调成本吃掉。
- 修复方向：按真实变更路径划出所有权边界（哪一层拥有这条决定），把"一起变的东西放在一起"；不要靠再加一层转发来缓冲。

**不该报**：同一限界上下文内的协同改动是正常的；组合根的装配变化不算传播。

## R4 偶然复杂（架构视角）

- 症状：为尚不存在的需求预建抽象层、适配器或分布式结构；整层架构不产生价值；**二次系统效应**——第二版比第一版庞大得多，通用性超出当前需要；长期战术性捷径累积成"每个新功能都要先跟现有结构搏斗"。
- 出处：Fowler Speculative Generality；Brooks 第 5 章二次系统效应；McConnell YAGNI；Ousterhout 战略式与战术式编程。
- 后果：实施成本被脚手架吞掉，简单需求也变慢。
- 修复方向：以"当前是否有第二个真实消费者"为删除标准，逐层收拢；不需要的扩展点直接删，而不是留着"以后可能用"。

**不该报**：吸收供应商变动的薄包装、对外部协议的 switch 都可能是合理设计；第二版更大不等于二次系统效应。

## R5 依赖失序（架构视角）

- 症状：模块间循环依赖；领域层直接依赖具体数据库驱动或 HTTP 客户端；稳定组件依赖频繁变动的组件；抽象依赖具体实现；接口隔离违规（实现方只需用一部分却被迫实现全部）；对传递依赖直接版本钉死造成升级阻塞。
- 出处：Martin ADP / DIP / SDP / SAP / ISP；Brooks 第 4 章概念完整性；《Google 软件工程》第 21 章依赖管理。
- 后果：基础设施变更级联进领域；循环让隔离、替换与并行开发都变得不可能。
- 修复方向：在真正的跨界处引入接口或适配器；优先打破环（哪怕是先抽出一个稳定的窄接口），而不是调整文件位置。

**不该报**：编排层或组合根的高扇出；适配器同时依赖领域与基础设施（它本就在边界做转换）；稳定的门面覆盖多个叶子依赖。

## R6 领域失真（架构视角）

- 症状：业务逻辑全在服务层，领域对象只有数据；跨限界上下文不做转换或防腐层；模块名与业务语言不一致；值对象被当成带生命周期的实体。
- 出处：Evans 领域模型 / 统一语言 / 限界上下文；Fowler Data Class / Feature Envy；Martin LSP。
- 后果：模型逐渐变成对表结构画皮，语义冲突在集成处才暴露。
- 修复方向：把决定性的业务规则搬回它所属的边界；跨上下文引入防腐层，而不是直接共享数据结构。

**不该报**：CRUD 密集流程用事务脚本是合理的；DTO、持久化记录、API 载荷模型允许只有数据。

## 技术债排序：痛点 × 面

全仓扫描后不要凭感觉排优先级。对每条发现打两个 1–3 分：

**痛点（1–3）**：它今天拖慢开发到什么程度
- 3：开发者主动回避碰这块，几乎每次改动都带出问题
- 2：这块明显比其他区域慢，加一个字段要花 2–3 倍时间
- 1：是质量问题，但目前没有造成实际痛感

**面（1–3）**：它影响多少文件、模块或人
- 3：5 个以上模块，或全体开发者
- 2：2–4 个模块，或团队的一部分
- 1：孤立在一个模块或一个人手上

**优先级 = 痛点 × 面**（最高 9）

| 分值 | 归类 | 动作 |
|---|---|---|
| 7–9 | 关键债务 | 下个迭代处理 |
| 4–6 | 排期债务 | 本季度内规划 |
| 1–3 | 观察债务 | 记录并观察，不主动投入 |

排序时先列全部发现再打分，避免被最先看到的条目锚定。打分依据要可核对：写清哪条现象支撑这个分数，而不是只给数字。

## 与审查员清单的分工

- 函数级可读性、命名、魔数、Flag Argument → 审查员的 R1。
- 测试套件的有效性、mock 比例、覆盖率假象 → 审查员的 T1–T6。
- 本文只处理模块边界、依赖方向、领域表达、抽象收益与债务排序。
