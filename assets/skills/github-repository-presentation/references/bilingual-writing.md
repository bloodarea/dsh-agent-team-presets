# 双语写作与 GitHub 项目信息规范

## 一、README 双语文件规则

- 主 `README.md` 写英文（GitHub 默认展示），`README.zh.md` 写中文。
- 两份 README 都在顶部提供指向对方的语言切换链接，例如 `[中文](README.zh.md)` / `[English](README.md)`。
- 两份内容完整对应、各自可独立阅读，章节顺序一致。
- 技术名、命令、文件路径、代码和既有专有名词不强行翻译。
- 不在同一个 README 里逐段中英对照；使用两个独立文件。
- 中英文内容必须基于同一组已确认事实，功能状态、重要限制和链接保持一致。

## 二、其他公开文档的语言规则

- 补充文档写明适用语言。
- 若需要双语，使用两个独立文件并互相链接，不逐段中英对照。
- 不要求每一份低价值或仅服务特定受众的文档都机械提供双语版本；根据真实读者需求决定。
- README 只提供摘要和导航，详细文档不重复 README 全文。

## 三、统一文字标准

- 采用克制、自然、专业的表达，避免营销化形容词。
- 具体胜于空泛：说明项目做什么、适用于谁、如何开始、现有限制。
- 不把尚未验证的命令、计划功能或模型推断写成已实现事实。
- 中英文版本应表达相同事实和承诺；允许按语言习惯调整语序，不要求逐句直译。

## 四、GitHub Description

- 使用一条精炼的项目介绍，优先保证准确、自然和易检索。
- 遵守 GitHub 字符上限。
- 若双语信息确实无法在限制内准确表达，向用户提出取舍，不自行截断关键含义或擅自改成单语。

## 五、GitHub Topics

- 只使用真实领域、用途和生态关键词。
- 遵守 GitHub 当前格式与数量约束。
- Topics 本质是检索标签，不要求硬译成中英两套。
- 不添加与项目实际能力无关的热门词来增加曝光。

## 六、项目截图与演示

- 优先展示真实产品界面、真实工作流和已实现功能。
- 不使用容易被误解为实际产品能力的概念效果图。
- 截图、GIF 和图注在中英文页面中应保持事实一致；必要时提供本地化图注或素材。
