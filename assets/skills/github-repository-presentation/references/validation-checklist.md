# 文档治理执行流程与验收清单

## 一、执行流程

接到 README 或文档治理任务时，按以下顺序执行：

1. **确认任务范围**：是只优化 README，还是同时整理公开文档目录、`.gitignore`、Description、Topics 或 Release Notes。
2. **读取必要事实**：按任务读取现有 README、相关文档、项目入口、依赖配置、许可证、CI 配置、图片和版本信息；不无差别扫描整个仓库。
3. **识别文档归属**：区分项目入口、正式公开资料和内部研发记录；不把内部过程资料误放进公开 `docs/`。
4. **检查 Git 忽略规则**：确认根目录 `.gitignore` 是否包含 `/docs/internal/`；检查是否已有内部文件被 Git 跟踪。未经授权不执行索引移除或历史改写。
5. **设计 README 首屏**：确认 Banner、项目名称、Tagline、技术栈徽标和真实状态徽标。
6. **按固定顺序编写 README**：What Is This → Problem → Features → Quick Start → Documentation → 按需补充信息。
7. **整理公开文档**：必要时建立 `docs/README.md` 索引，并把详细内容放入合适的公开子目录；不为目录完整而创建或迁移无用文件。
8. **同步中英文内容**：保证两个 README 的章节顺序、事实、功能状态和链接一致。
9. **核对链接与事实**：检查图片路径、徽标目标、命令、文档链接、锚点、许可证和版本状态。
10. **汇报变更边界**：说明修改了哪些文件、哪些事实已验证、哪些内容待补，以及是否存在仍被 Git 跟踪的内部文件。

## 二、README 首页验收

- [ ] README 是否以真实、可访问的 Banner 作为第一个可见主体？
- [ ] Banner 是否能直观表达项目是什么，而非仅作装饰？
- [ ] 项目名称、Tagline 和中英文切换链接是否清晰？
- [ ] Shields.io 技术徽标是否真实、可点击且数量克制？
- [ ] License、Release、CI、Coverage 等状态徽标是否来自真实数据？
- [ ] README 是否遵循 What Is This → Problem → Features → Quick Start → Documentation 的阅读顺序？
- [ ] Quick Start 是否为最短可信路径，命令和预期结果是否准确？
- [ ] 详细 API、架构、配置和开发资料是否放在公开 `docs/`，而非挤入 README？
- [ ] `README.md` 与 `README.zh.md` 是否互链、内容完整对应且没有虚构或多余填充？

## 三、公开文档与内部文档验收

- [ ] `docs/README.md` 是否作为公开文档索引，且只链接实际存在的公开文档？
- [ ] `docs/` 是否主要包含当前实现、稳定约定和对外使用资料？
- [ ] 开发日志、实验失败记录、内部任务和未定稿方案是否归入本地 `docs/internal/`？
- [ ] 仓库根目录 `.gitignore` 是否包含 `/docs/internal/`？
- [ ] 是否确认内部文件没有继续被 Git 跟踪？如有，是否向用户说明并等待授权处理？
- [ ] README 和公开文档是否没有暴露内部目录链接或依赖内部记录？
- [ ] 正式 API、接口和技术定义是否有唯一权威来源？

## 四、其他项目信息与交付验收

- [ ] 安装、使用、许可证、重要链接和视觉素材是否与工作区事实相符？
- [ ] Description、Topics 与 README 是否保持一致？
- [ ] Release Notes、CHANGELOG 与 PR 描述是否为“完整中文段 + 完整英文段”，而不是逐句对照？
- [ ] 变更数量是否真实，是否保留必要升级警示？
- [ ] 是否只执行了本次授权的文件改动和远端操作？
- [ ] 交付时是否准确说明未验证、待补充和未执行事项？
