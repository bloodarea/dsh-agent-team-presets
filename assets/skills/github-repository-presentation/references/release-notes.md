# PR、Changelog 与 Release Notes 规范

本文件规定公开变更说明的双语表达与可读性。版本范围、变更事实、提交证据、版本判定和发布操作由 `git-release-hygiene` 或实际任务证据决定。

## 一、通用原则

- 使用完整中文版 + 完整英文版两个独立段落，不逐句对照、不左右并列。
- 中文完整内容在前，英文完整内容在后。
- 突出用户可感知变化，不贴实现细节、长日志或逐条 Commit。
- 类别、条目数和事实在中英文版本中完全一致。
- 不兼容变更、必要迁移和已知风险必须在两种语言里都写明。
- 无证据时不得宣称“无破坏性变更”。
- 版本范围、数量无法核实时标明待核实，不编造数字与日期，不把草稿说成已发布。

## 二、Release Notes 排版约束

GitHub 已有版本标题时，正文不再重复大标题。

1. **结构**：`## 中文` 与 `## English` 各写完整一份。
2. **变更数量**：中文使用 `新增 / 优化 / 修复`，英文使用 `Added / Improved / Fixed`。
3. **计数口径**：计数单位是归并后、面向用户的变更事项，不是代码行数、文件数或 Commit 数。
4. **分类**：无相应变化的类别直接省略，不保留空标题。
5. **提醒**：必要时增加“重要说明 / Important Notes”，两种语言内容保持一致。

## 三、固定结构示意

````markdown
## 中文

本次更新主要……。

**变更概览**：新增 X 项 · 优化 Y 项 · 修复 Z 项

**新增**
- 中文事项。

**优化**
- 中文事项。

**修复**
- 中文事项。

<!-- 仅在必要时增加“重要说明” -->

## English

This release focuses on ... .

**Summary**: Added X · Improved Y · Fixed Z

**Added**
- English item.

**Improved**
- English item.

**Fixed**
- English item.

<!-- Add "Important Notes" only when needed -->
````

`X/Y/Z` 仅为槽位；最终只保留有变更且计数可核实的类别，版本与日期使用已确认信息。

## 四、PR 与 Changelog

- PR 描述、Changelog 和 Release Notes 使用完整中文段落在前、完整英文段落在后的结构。
- PR 内容说明变更目的、用户可感知影响、测试情况和必要迁移事项；不把开发日志复制到公开 PR 描述。
- Changelog 按已发布版本记录真实变化；不要将尚未发布的计划写成已发布事实。
- 变更归属、Git 证据、版本判定和发布流程遵循 `git-release-hygiene`。
