# Leader Medium Task Workflow

## 目标

以较低协调成本完成有界中程任务。队长负责拆分、派发、跟踪和验收；执行者负责具体实现。

## 触发判断

适用于目标明确、范围可控、包含若干相关工作项，且无需跨多轮持久化项目计划的任务。

- 单一明确修改：直接派发，使用执行者短程工作流。
- 多个相关子任务、一个有界执行周期：使用本 Skill。
- 多轮交付、跨阶段依赖、持续需求对齐或长期验收：转入 `leader-long-task-orchestration`。

## 工作流程

1. **明确结果**：提炼目标、范围、约束和验收条件。影响用户功能或界面的关键歧义先向用户确认。
2. **检查必要事实**：优先复用已有事实；若有两个或以上独立调查方向，必须调用 `agent-subagent-orchestration` 并行探查，按需加载 `agent-subagent-orchestration` 技能并读取其中的 leader-discovery.md 参考文件；避免队长单线程扫描全部范围。
3. **轻量拆分**：按可独立交付的结果拆分工作项，标明依赖、负责人和验收条件。避免为拆分而拆分。
4. **分派任务**：使用宿主 Team Task Board 管理成员工作项；任务指令采用结构化英语，提供完成任务所需的最小上下文。
5. **管理协调动作**：队长使用自己的 Todo 记录待办的协调、检查和决策动作。成员任务留在 Task Board，不复制到 Todo。
6. **跟踪与调整**：依据任务板状态处理阻塞和依赖。影响产品范围、行为、成本或风险的变化才升级给用户。
7. **集成验收**：检查各项交付及整体结果，核对验收条件和证据；汇报完成情况、遗留项和风险。

技术方案涉及跨层架构、重大选型或复杂故障时，队长按需调用 `fullstack-advisor`；普通实现细节由团队自行决定。

## 工作约束

- 不为中程任务创建持久化 `DELIVERY-PLAN.md`；使用宿主已有任务板和 Todo。
- 不重复派发已完成的调查，不向成员粘贴整段历史上下文。
- 多个独立实现工作包交由执行者时，提示其按 `agent-subagent-orchestration` 并行执行；单一小任务不强制拆分。
- 不把普通技术细节问题转交用户；团队在已批准的产品边界内自行决策。
- 不以成员自述代替验收证据。
- 任务扩大为多轮项目时，升级到长程工作流并建立持久化计划。

## 升级与用户裁决

- 新发现的技术细节由团队在现有边界内处理，并记录影响任务结果的重要决定。
- 功能行为、界面预期或验收口径不明确时，先向用户确认再派发受影响工作。
- 需要新增阶段、长期跨会话跟踪或显著扩大范围时，暂停扩展并升级到长程工作流。
- 升级时转交已确认目标、已完成调查、现有任务 ID、依赖、交付证据和未决事项，避免重新调查。

## 完成标准

队长检查所有工作项的交付物和验证结果，确认整体验收条件满足后再向用户报告完成。未通过或未运行的检查应明确列出；阻塞项说明原因、影响和所需决策。

## 按需参考

- 派发、成员通信与结果汇总：由队长专属 `agent-leader-communication` 负责，本 Skill 不重复定义通信契约。
