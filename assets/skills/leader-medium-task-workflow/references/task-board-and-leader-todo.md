# Team Task Board 与 Leader Todo 使用规范

## 两种载体的职责

| 载体 | 管理对象 | 典型内容 |
|---|---|---|
| Team Task Board | 团队成员的交付任务 | 目标、负责人、依赖、执行状态、交付结果 |
| Leader Todo | 队长自己的协调动作 | 等待决策、检查依赖、审阅结果、安排下一步 |

Task Board 是成员执行任务的事实来源；Leader Todo 是队长管理自身行动的清单。

## Task Board 工作项

每个工作项尽量包含：

- **ID**：便于引用的短标识。
- **Objective**：预期结果。
- **Owner**：执行成员。
- **Scope**：允许修改或调查的范围。
- **Acceptance**：可验证的完成条件。
- **Dependencies**：前置工作项。
- **Status**：宿主任务板支持的状态。
- **Output**：结果、文件位置和验证证据。

一个工作项应有一个清晰的主要交付结果。只有确实能并行且不会争用同一资源时才拆成多个成员任务。

## Leader Todo

Todo 只记录队长下一步需要亲自完成的动作，例如等待某项交付后集成检查、审查顾问意见、向用户确认产品行为、更新最终验收汇报。成员正在执行的每个子任务不应再完整复制到 Todo。

## 状态与验收

任务板状态表示执行进度；最终验收表示交付是否满足要求。两者不可混用。执行者将工作项标记完成后，队长仍需检查交付物和验收证据。

## 控制协调成本

- 优先批量派发互不依赖的任务。
- 仅在依赖完成、出现阻塞或需要决策时更新队长。
- 复用任务 ID 和已有证据，不重复转述完整背景。
- 不为短中程任务另建重复的 Markdown 进度表。
- 任务超出一个有界执行周期时，重新判断是否升级为长程任务。
