# Git 变更与版本交付验收清单

## 变更事实

- [ ] 已检查相关 `git status`、diff、分支和提交范围。
- [ ] 已区分用户已有修改、本次任务修改和无关文件。
- [ ] 变更事项按用户可感知的独立结果归并，没有按文件数或 Commit 数机械罗列。
- [ ] 未将计划功能、未验证结果或内部开发记录写成已交付能力。

## Git 安全

- [ ] 没有擅自暂存全部文件、删除未知文件或覆盖用户修改。
- [ ] 高风险 Git 操作已说明影响、恢复方式并获得明确授权。
- [ ] Commit、Push、Build、Test、Release 状态分别核实。
- [ ] 没有把本地 Tag、Release 草稿或准备好的文案误报为已公开发布。

## GitHub Release

- [ ] 中文完整区块在前，英文完整区块在后。
- [ ] 没有逐条中英交替或 `中文 / English` 混排。
- [ ] 开头摘要具体说明版本重点，没有空泛套话。
- [ ] 默认没有强制数量统计；如有统计，口径可核实。
- [ ] 分类只保留有内容的部分，分类与事项匹配。
- [ ] 每条 Bullet 说明具体行为变化及用户影响。
- [ ] 重要限制、兼容性变化和迁移步骤醒目且双语一致。
- [ ] 贡献者署名有 PR 或 Commit 等可靠依据。
- [ ] Full Changelog 的仓库、起止 Tag 和比较范围均已核实。
- [ ] 没有重复 GitHub Release 标题中已经显示的版本信息。

## Changelog 与 PR

- [ ] Changelog 按版本组织，中文和英文分别完整成区块。
- [ ] PR 描述说明背景、主要变更、实际验证及必要风险。
- [ ] 测试结果只陈述实际执行过的检查。
- [ ] 没有强迫 PR 套用 Release 的分类体系。
- [ ] 版本号、日期、链接和迁移说明均可核实。

## 最终交付

- [ ] 已说明实际修改、提交、推送、构建、测试或发布情况。
- [ ] 已列出尚未执行、无法验证或需要进一步授权的事项。
- [ ] 没有虚构成功状态、贡献者、日期或版本范围。
