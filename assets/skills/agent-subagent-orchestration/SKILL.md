# Agent Subagent Orchestration

## 目标与适用角色

将可独立完成的探查或实现工作交给独立上下文中的孙代理，缩短串行等待并隔离长任务上下文。仅供 **Leader** 与 **Executor** 使用；**Fullstack Advisor 不创建孙代理**。

本 Skill 规定编排方式，不假定宿主的具体创建工具、参数或并发 API。使用宿主实际提供的子代理能力；能力不可用时如实说明并退回串行执行。

## 强制触发

满足以下条件时，必须显式创建孙代理，不得仅因当前会话可以继续完成任务，或只考虑即时委派开销而默认串行：

- **Leader**：存在两个或以上实质独立的工程事实探查方向，例如架构/代码路径、模块实现、测试体系、平台适配或文档契约。
- **Executor**：任务已具备明确目标和验收条件，且包含两个或以上可独立实现、可分配边界的工作包。

先判断依赖和冲突，再决定并行方式。多个工作包存在严格先后关系时按阶段并行；共享接口未确定时先由父代理或顾问确定契约。

## 不创建的情况

- 单一、轻量、局部任务，单个代理可快速完成。
- 工作包高度耦合，必须连续共享大量临时状态。
- 多个工作包必然同时修改同一文件或同一不可分割资源。
- 功能、业务规则或界面要求尚有关键歧义，且并行实现会造成返工。
- 宿主不支持子代理，或当前并发/名额/权限限制不允许创建。

不得以“省 Token”为由跳过符合强制触发条件的并行任务；也不得为了使用子代理而制造无价值的拆分。

## 编排流程

1. **判定模式**：Leader 使用 `DISCOVERY`；Executor 使用 `IMPLEMENTATION`。
2. **划分工作包**：每个孙代理只负责一个独立问题或交付物，明确范围、输入、边界和验收条件。
3. **分配所有权**：探查任务划分独立调查域；编码任务划分文件/模块所有权，避免并发写入冲突。
4. **显式创建**：通过宿主原生子代理能力启动任务。默认同时运行 2–3 个；超过时分批，始终服从宿主限制。
5. **回收摘要**：只接收结构化结论、证据位置、验证结果和阻塞。详细日志按需索取。
6. **父代理集成**：父代理负责去重、处理冲突、复核关键事实、集成修改及最终验收，不把整合责任转给孙代理。

## 层级与权限

- 孙代理不得继续创建子代理；本团队工作树止于孙代理层。
- 孙代理只执行分派范围，不自行扩大目标、改变验收标准或向用户作产品承诺。
- 孙代理不负责团队总协调；父代理保留任务状态、整体上下文和集成责任。
- 代码修改、测试、提交、推送、发布及外部操作遵循父任务授权和项目权限。
- 顾问保持单线程；队长可先组织事实探查，再向顾问提交精简事实和决策问题。
