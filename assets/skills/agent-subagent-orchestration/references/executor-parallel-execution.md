# Executor Parallel Execution

## 启动条件

执行者收到任务后，先确认目标、范围、接口契约和验收条件。若任务包含两个或以上实质独立、可分别验收的编码工作包，必须显式使用孙代理并行执行；不得只因单会话可以逐项完成或即时委派有开销而默认串行。

单一局部修改、强依赖链、共享状态密集或文件冲突明显时，由执行者自行串行完成或分阶段执行。

## 并行前置条件

并行前必须明确：

- 每个工作包的目标和验收条件。
- 文件/模块所有权，尽量做到修改范围互斥。
- 共享接口、数据结构和跨模块约定。
- 各孙代理负责的局部测试与父代理负责的集成测试。
- 依赖顺序、集成顺序和冲突处理方式。

接口尚未确定时，执行者先与队长对齐，必要时请顾问提供技术契约，再启动并行编码。

## 工作包分配

适合并行：
- 不同模块且文件所有权互斥的实现。
- 独立适配器或平台实现。
- 互不依赖的测试补充与文档更新（仅在内容边界清楚时）。

不适合同时并行：
- 多人修改同一个核心文件、共享配置或同一迁移文件。
- 一个工作包的接口尚未由另一个工作包确定。
- 多人同时改动同一公共数据结构或生成产物。

发生共享文件需求时，指定唯一写入者；其他代理提交建议或补丁说明，由父代理统一集成。

## 执行者职责

1. 先建立工作包清单和文件所有权，再创建孙代理。
2. 每个孙代理只接收自己的任务卡和必要上下文。
3. 明确子任务的局部测试范围，避免所有代理重复运行完整测试套件。
4. 收到结果后检查实际 diff、接口兼容和文件冲突。
5. 执行者负责整合、解决冲突、运行跨模块回归并形成最终交付。
6. 子任务失败时，由执行者判断修复、重新分派或串行接管；不得让孙代理自行递归委派。

## 变更权限

孙代理只修改分派给自己的文件和范围。不得擅自修改共享契约、扩大重构、提交/推送/发布或执行破坏性 Git 操作，除非父任务明确授权。发现范围外必要变更时先报告。

## 验收

父执行者必须亲自确认：
- 各工作包的实际变更已集成。
- 公共接口和跨模块行为一致。
- 局部测试与最终集成测试状态明确。
- 未完成项、风险和未运行验证已报告。

子代理的 `DONE` 不等于整体任务 `DONE`。
